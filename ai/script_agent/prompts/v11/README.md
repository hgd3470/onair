# v11: 편집 요구사항의 추적과 안정적인 수정

사용자 피드백을 일반 지침에만 넣던 구조를 보완했다. `editorial_brief`는 분석·생성·수정·재검토에 함께 전달된다. 검토는 항목별 실제 문장 근거와 충족 여부를 먼저 출력한다. 코드가 누락/중복/미충족을 수정 또는 hold로 연결한다. 사람 승인을 자동으로 만드는 기능은 아니다.

기존 지침을 중복 없이 정리하고, 용어→범주 연결, 원문 예시, 장면 도입, 질문과 결말 회수, 성경 출처 안내, 주체·추정 강도 보존을 유지했다. 원문 인용은 그대로 검사하며, 수정 카드가 바뀌지 않으면 null로 보내 불필요한 전체 재출력을 줄인다.

실제 응답에서 MAX_TOKENS와 내부 추론 토큰 사용량이 확인되어 생성 출력 상한을 16,000에서 32,000으로 늘렸다. Gemini/OpenAI 모델과 medium 수준은 유지한다. 모델 응답 본문·키를 저장하지 않고 실패 종료 사유와 허용된 토큰 수만 남긴다. 과거 C07의 종료 사유는 소급해 확정하지 않는다.

마크다운 강조 기호·공백만 다른 인용은 유일한 원문 구간으로 복원하고 위치·전후 인용을 별도 기록한다. 원문 자체는 변경하지 않는다. 부정어·숫자·절 번호·문장부호의 차이나 모호한 일치는 허용하지 않는다.

원문낭독형의 원문 보존, 40자·한글 읽기, 사실 ID·권리 근거, 자동 수정 최대 두 번과 hold 계약은 유지한다. 이전 v7~v10의 프롬프트와 실행 결과는 보존한다.

검증과 최종 대본은 로컬 `scratch/feedback-resolution-20261108/`의 결과 안내를 참조한다. 실험 대본과 외부 원문은 Git/배포에서 제외한다.

요청 대기 한도는 300초다. 전송 실패는 기존 `transport_or_timeout` 코드를 유지하되 새 진단의 `transport_failure`에서 시간 초과와 네트워크 오류를 구별한다. 원문 오류 메시지는 저장하지 않으며 자동 재시도하지 않는다. 과거 진단 없는 실패의 정확한 종류는 소급해 단정하지 않는다.
