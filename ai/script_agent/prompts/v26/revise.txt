현재 원고의 실제 미해결 피드백과 editorial_brief를 함께 고친다. 출력은 {draft, material}이다. draft는 수정한 전체 대본·claims·changes다. 사실 카드 변경이 필요하지 않으면 material=null로 기존 카드를 재사용한다. 카드를 바꾸면 전체를 반환하되 기존 ID를 삭제·재사용하지 않고 필요한 근거만 새 ID로 추가한다. production_type/category와 원문의 유효 quote를 유지한다.
각색형: 새 장면이 원문과 다르다는 이유만으로 원문의 특정 소품·금액·직급·행동을 복원하지 않는다. 허용된 창작은 fiction/new로 분류한다. 식별 문제는 관련 세부 조합 전체를 보고 불필요한 장면을 덜거나 다시 설계한다. 단어 하나를 바꾸고 같은 행동 사슬을 유지하지 않는다.
사실형: 주장 강도를 근거 수준으로 돌리고 없는 인과·기전·대상을 제거하며 조건·예외·범위를 되살린다. 지시어를 실제 대상명으로 바꾸고 전문용어와 수치는 근거 안에서 쉽게 푼다. 부정의 대상을 넓히지 않는다. 여러 관점을 압축하느라 어려워졌다면 중심 질문의 범위를 좁혀 한 설명을 제대로 전달한다.
문장 0은 전체 문제다. changes에는 실제 변경과 근거상 받아들이지 않은 제안을 구분해 설명한다. 이미 해결된 장점은 유지한다. 근거 없는 제안은 따르지 않되 같은 취지를 근거 안에서 해결한다. 마지막 답을 고치며 관점·가능성을 확정 사실로 만들지 않는다. 불필요한 반복·부수 정보를 덜어 용어·조건·마무리 공간을 확보한다.
반환 전에 모든 문장의 공백·문장부호 포함 40자 상한과 한글 읽기, 전체 70~130% 분량, claims 번호·분류·근거, editorial_brief 충족을 다시 확인한다. 문장을 나눠도 각 문장의 주어와 대상이 분명해야 한다. 현재 원고의 실질 미해결 결함만 unresolved에 기록한다.

v18 수정: 추상어를 다른 추상 동의어로 바꾸지 말고 원문이 말하는 실제 기능·대상을 명시한다. 위험한 각색 해결은 허용된 새 장면 안에서 도움과 인물의 선택을 일관되게 고친다. 결말 반복은 새 훈훈한 문장으로 교체하지 말고 이미 갈등이 닫힌 행동/결과에서 끝낸다. 분량 부족 여부는 전체 허용 범위로 확인하며 감정 반복으로 채우지 않는다.

특징적 세부 조합 지적을 고칠 때는 단어 교체를 멈추고 원문과 대응되는 오해·해결 계기를 함께 점검한다. 같은 소유 관계나 소실 경로가 핵심 식별 근거라면 허용된 각색 범위에서 다른 단서·선택·행동으로 재구성한다. 보편적인 갈등의 흐름 자체는 유지할 수 있다.

사실 문장별로 claims.fact_ids가 가리키는 카드의 conditions를 하나씩 대조한다. 원문에 실제 있는 조건 중 현재 주장에 필요한 것은 대본의 해당 문장이나 바로 연결된 문맥에 명시되어야 한다. 카드에 있다고 본문에도 전달된 것으로 간주하지 않는다. 앞/뒤·비워진 뒤·특정 대상에 한해 같은 성립 조건을 압축하며 없애지 않는다. 현재 주장과 무관한 카드 조건까지 억지로 붙이지는 않는다.

인과 접속어(때문에/덕분에/이를 통해/그래서)가 있는 사실 문장은 원인과 결과를 각각 짚고 그 연결 자체가 원문에 있는지 확인한다. 한 기술의 별개 효과 두 개를 앞뒤에 배치한 뒤 앞 효과가 뒤 효과를 일으킨다고 연결하지 않는다. 연결 근거가 없으면 실제 주체를 다시 쓰고 두 효과를 별도로 설명한다.

quote는 렌더링된 화면의 글이 아니라 source_text 문자열의 연속 구간이다. 예를 들어 원문이 **용어**는 설명이다. 라면 quote에서 **용어**를 용어로 정리하지 않는다. 구간 중간의 별표·각주도 그대로 포함한다. 설명을 쉽게 고치는 작업은 text/conditions/script에서만 한다. 긴 인용에서 표기를 놓치기 쉽다면 주장에 필요한 더 짧은 연속 구간을 정확히 선택한다.

반환 직전 최종 script 배열의 모든 원소를 공백·문장부호 포함 실제 글자 수로 다시 확인한다. 40자를 넘으면 조건·대상을 보존하며 완결 문장으로 나누고 claims를 재번호화한다. 수정 메모의 길이가 아니라 최종 본문을 검사한다. 마지막 두 문장의 반복을 제거하며 도입 질문의 답이나 관점의 범위를 명확하게 닫는다.

수정 범위 보정: 선택적 편집 권고를 해소하려고 근거 있는 본문을 다시 구성하거나 부수 설명을 늘리지 않는다. 피드백이 단순 명료화·취향인지, 현재 문맥에서 실제 의미·근거·필수 제약의 결함인지 먼저 확인한다. 실질 결함은 고치고, 근거 없는 제안은 changes에 이유를 기록한다. 과거 문장 번호와 예시 방법은 현재 원고에서 요구의 목적을 실현하는 데 필요한 경우에만 적용한다. 사용자의 명시적 필수 요구와 코드 검사 실패는 계속 해결한다.

뉴스 관련 지적을 수정할 때 제목의 예정·완료 상태와 공식 발표·제도 기준의 기관 귀속을 함께 다시 점검한다. 기관 근거는 각 [검증 사실] 블록의 귀속 주체에도 존재한다. 기관을 지워 통과하려 하지 말고 정확히 인계한다. 숫자/지수명 읽기는 표기만 고치며 값·기준을 유지한다. 바꾼 문장의 길이와 완결성도 확인한다. 사실 카드가 바뀌지 않으면 material=null을 사용하고, 무관한 문장과 사실을 수정하지 않는다.

계획 보도는 행위 미완료의 증거가 아니다. ‘표명하기로 했다고 밝혔다’는 확인된 계획 발표로 쓰며 ‘아직 지지하지 않았다’, ‘이미 지지를 완료한 것은 아니다’ 같은 부정 사실을 근거 없이 추론하지 않는다. 한 문장 안의 계획 표지를 보존하는 것으로 충분하고 완료/미완료를 추가로 단정하는 해설을 붙이지 않는다. 뉴스의 자료 기준일과 청취/방송 시각은 다르다. 기준일이 11월 11일인 자료를 ‘11월 11일 아침 브리핑’으로 바꾸지 않는다. 발표 기사 시각이 없을 때 아침·오전 등 시각을 추정하지 않는다.

뉴스 수정에서 승인된 v6 의견 인용에 필요한 매체명만 남기고 나머지 출처 안내는 낭독문에서 제거하고 내부 메타데이터·인용·근거를 보존한다. 필요한 기관 귀속을 보도 매체명으로 대체하지 않는다. 첫 문장은 실제 사건으로 고치고 날짜는 사건에 연결한다. 한국시간 안내와 해요/죠 말투를 제거한다. 문장 길이를 맞추려고 비교 기준을 빼거나 해요체로 되돌리지 않는다.

뉴스 도입 구체성: 첫 문장을 ‘새 기준/새 방침/새 대책을 알렸다’, ‘합의에 나섰다’처럼 내용이 빈 예고 문장으로 쓰지 않는다. 허용·유예·증가·감소 등 실제로 확인된 변화와 그 대상을 첫 문장에 담는다. 실제 잠정 합의를 합의 착수로 약화하지 않는다. 발표 주체와 핵심 변화가 길면 근거가 명확한 통상 약칭(식품의약품안전처→식약처, 금융위원회→금융위 등)을 쓸 수 있다. 낯선 기관은 함부로 축약하지 않는다. 현재 달의 발표일은 일자 중심으로 말할 수 있고 연도 전체를 독립 문장으로 늘이지 않는다. 통계의 측정 월·연도 등 의미에 필요한 기간은 남긴다. 첫 두 문장의 역할은 서로 달라야 하며 두 번 연속 ‘발표했다/알렸다’로 같은 정보를 반복하지 않는다.
분석 outline에는 실제 낭독할 도입 문장 1~2개와 해당 fact_id를 먼저 설계한다. 생성/수정 때 이 계획을 확인해 구체적인 사건이 바로 드러나는지 읽어 본다. 비교 기준을 줄이려고 ‘전 거래일’을 ‘직전’만으로 바꾸거나 전체 모집단/분모를 빼지 않는다. 40자를 넘으면 문장을 재구성하고 분명한 앞 문맥으로 연결한다. 해요체나 조건 삭제로 길이를 줄이지 않는다.

원문 인계 v6: common.txt의 선택적 의견 인용 계약을 따른다. 의견을 수정해도 정확한 근거·귀속·추정 강도를 유지한다. 인용을 삭제하면 해당 claims도 정리한다. 직접 인용의 문구나 mode를 바꿔 길이를 줄이지 말고 부적합하면 생략한다.

근거 카드 ID 규칙: material.facts의 모든 id는 종류와 무관하게 f1, f2, f3… 형식이다. opinion 카드도 f번호를 쓴다. 수집기의 O1/F1은 conditions의 연결 값일 뿐 material 카드 id가 아니다. 예: {"id":"f6","kind":"opinion","conditions":["O1"]}. claims.fact_ids는 해당 f번호를 참조한다.
